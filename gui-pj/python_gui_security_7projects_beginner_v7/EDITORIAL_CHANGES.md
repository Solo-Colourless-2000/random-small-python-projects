# 今回の実質的な校閲記録（2026-11-10）

本記録は回数の水増しを目的としない。元ZIPの完成ソース、HTML教材、サンプル、既存テストを実際に読み、以下の不正・曖昧・境界ケースを再現してから修正した。

## 実際に発見した問題と修正理由

### 02: HSTSの巨大な数字で解析が例外終了する

旧コードは`int(age_items[0].group(1))`を使用。例えば`max-age=`の後に5000桁の9を続けると、Pythonの整数文字列変換制限によりValueErrorが発生し、解析処理が途中終了する。正数判定だけなら数値化は不要。ASCII数字の並びの中に0以外の文字があるかを調べるよう変更し、5000桁の9と5000桁の0、矛盾した2個のmax-age指定を別々にテストした。実際のブラウザーのHSTS採用可否まで保証しないことも明記。

### 02: 入力欄が空でも調査メモだけが表示されていた

有効なヘッダーが一つもないテキストをINPUT ERRORにする。欠落と「解析対象がない」は区別した方が初学者に説明しやすい。

### 03: ホストビットのあるCIDRが暗黙に広げられる

旧コードの`strict=False`では`192.0.2.17/24`が`192.0.2.0/24`に正規化され、入力の意図より広い範囲に見えてしまう。これは学習者の誤読を誘発するので`strict=True`に変更した。正しく広い範囲を記したいなら`192.0.2.0/24`、特定の1台なら`192.0.2.17/32`。マニュアルの旧説明や実験項目をすべて修正した。

### 03: 極端に長いport値

ASCIIでも異常に長い数値文字列は整数変換の例外を引き起こす可能性があった。事前に桁数を制限し、1..65535のみ受け付ける条件を明記した。

### 04: IPv6スコープ識別子

標準ライブラリの`ipaddress.ip_address()`は`fe80::1%eth0`のような表記を受け取れる。しかしIOCとして同じIPv6アドレスを機器固有の名前に依存させると、正規化の意図を学びにくい。この教材では`%`を含むスコープ識別子を明示的に拒否することにした。

### 05: 異なるフォルダーをスキャンしてから比較拒否していた

旧コードは`current = snapshot(current_dir)`の後でベースラインとフォルダーパスの相違を確認。ベースラインが存在しない・フォルダーが違う場合、そもそもファイルを読まずにエラーにできる。順序を変更した。これは競合状態に対する完全な保護を意味しない。

### 06: Fromが2本あるのに「Reply-Toは同じドメイン」と表示

旧コードはFromが複数あっても先頭Fromのドメインを採用し、同じReply-ToならSEENを出した。実際に二つのFromヘッダーで再現。Fromが一つで正しく解析できる場合だけ比較し、曖昧ならCHECKとするよう変更した。ドメイン長の検査も追加。

### 01/03/04: CSVにファイルサイズ上限がなかった

行数制限だけでは、一つの巨大なセルを含むファイルを読み込む場合のコストを制限できない。各CSV読み込み前に最大1 MiBのファイルサイズを確認する小規模な練習向け防御を設けた。チェック後に第三者がファイルを変更する競合状態までは防止していない。

### 解説とソースのずれ

コード修正後、114行分の行別解説で58件の参照行番号が旧位置を指していた。すべて現行ソースへ照合し、変更された行の説明2件と短すぎる説明5件も改訂。STEP分割28ブロックと完成コード7本の連結一致は自動テストで維持する。

### HTML上の新しい検索項目

追加した解説表の検索対象要素のうち122箇所にIDがなかった。検索結果から当該項目へ移動できないためユニークIDを追加。7つの新しい表をスクロール可能なラッパー内に置き、狭い画面でのレイアウト崩れも防いだ。

## 35観点を超える作業で意識したこと

- 判定が出ても、その結果だけからインシデントや脆弱性を断定しない説明を各作品へ追記。
- 「どの入力が、どの辞書・リスト・変数へ入り、どのGUI行になるか」を7作品で追跡。
